# Ревью-агент писал в закрытые для агентов PR — стоп-метки и severity-разметка

## Ситуация

Инвариант «после стоп-слова ни один агент не пишет в ветку» держался на добросовестности: агент-закрыватель метку ставил, но сам себя ею не останавливал, а ревью-агент выдавал четвёртый круг ревью там, где цикл правок уже завершён стоп-словом. Бюджет LLM тратился на PR, не нуждающийся в агентах.

## Причина

Ни один потребитель события не проверял стоп-метки: событие с меткой обрабатывалось так же, как обычное. Классификацию замечаний ревью-агент не размечал, и агент-закрыватель классифицировал сам — слабой моделью и с завышением класса; лимит из трёх кругов правок расходовался на мелочах (нейминг).

## Решение

Реализован протокол взаимодействия агентов v1 (`webhook.py`):

- событие с меткой `pr-closer:closed` или `agents:off` отбрасывается **на разборе payload** — до обращения к API и к модели: метки уже приходят вместе с событием, отказ не стоит ни одного запроса. Проверка действует и на явные команды в комментариях: рубильник, который обходится командой `/review`, рубильником не является. Снятие метки возвращает PR в оборот без перезапуска (покрыто тестом);
- каждое замечание ревью начинается с машиночитаемой строки `severity: blocker|major|nit` (через `extra_instructions` в `.pr_agent.toml`) — этим контрактом управляется цикл правок: круг продлевают только `blocker` и `major`, `nit` — нет. Инструкция прямо говорит: при неуверенности класс понижается — ложный `blocker` гоняет цикл впустую, ложный `nit` уезжает в follow-up, цена ошибок разная.

## Как проверить

```
cd self-hosted && python3 -m unittest discover -s . -p 'test_*.py'
```

181 тест (было 174). Вживую: поставить на PR метку `agents:off` → ревью-агент молчит; снять → возвращается в оборот.

## Уроки

- Стоп-сигналы между агентами должны проверяться на самом дешёвом уровне — до любого похода в API или модель: метки приходят в payload бесплатно.
- Машиночитаемая severity-разметка замечаний — контракт между агентами: без неё классификацию делает тот, кто хуже оснащён, и лимиты тратятся не туда.
