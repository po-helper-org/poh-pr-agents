# Self-hosted ревью-бот падал «в тишине» — событие терялось без алерта и следа

## Ситуация

Автоматическое ревью на PR приходило через раз: webhook отвечал `200`, фоновый вызов LLM зависал или падал, в PR ничего не появлялось, никто не узнавал. Ни алерта, ни комментария, ни следа в журналах — событие просто терялось. Владелец узнавал о сбое часами позже, по молчанию бота в живом PR.

## Причина

Архитектура допускала тихую потерю событий. Webhook-путь сразу отвечал `200`, а вся дальнейшая обработка шла в одном «пожарном» фоновом вызове без очереди, идемпотентности и контроля завершения. Зависший или упавший вызов никто не подхватывал заново: ни ретрая, ни DLQ, ни свипера, который заметил бы «проглоченное» событие. Контракт был «нулевые ошибки», а не «нет тихих падений».

## Решение

Добавлен слой надёжности `self-hosted/reliability/` — event-driven конвейер поверх ревью-агента, stdlib-only, без внешних зависимостей:

- приём webhook с проверкой HMAC-подписи и dedup по `delivery_id`;
- durable-очередь с at-least-once, visibility-timeout redelivery, DLQ и честностью по партициям;
- worker с per-task таймаутом, state machine с CAS;
- reconciliation-свипер: застрявшие и пропущенные события находит и дозапускает;
- при попадании задачи в DLQ бот оставляет в PR идемпотентный видимый комментарий (upsert, не плодит дубли).

Контракт переформулирован со «всегда успех» на SLO: нет тихих падений, гарантированное eventual-завершение, идемпотентность, наблюдаемость. Каждое срезовое ревью перед мержем делал независимый субагент-критик; так поймали и исправили 4 HIGH и ряд Medium до мержа. На момент мержа логика покрыта 82 unittest и не была ещё развёрнута вживую — деплой-обвязка и фазы масштабирования остались в follow-up.

## Как проверить

```
cd self-hosted && python3 -m unittest discover -s reliability/tests -t . -v
```

82/82 OK, без внешних зависимостей. Вживую: открыть PR, убедиться что при сбое LLM в PR появляется видимый комментарий, а не тишина.

## Уроки

- Ответ `200` на webhook ничего не гарантирует — он лишь о приёме, не о выполнении: без durable-очереди и свипера любой фоновый сбой остаётся тихим.
- «Не молчать» дешевле «всегда успевать»: видимый коммент о сбое стоил дешевле гарантии успеха, а информативность для владельца выше.
- Порог валидации нужно поднять на входе — независимое adversarial-ревью субагентом перед мержем поймало 4 HIGH, которые обычный само-ревью пропускает.
