# Пойманные сбои были видны только строкой в логах контейнера — Sentry делает их адресуемыми

## Ситуация

Слой надёжности честно ловил сбои (задача ушла в dead-letter, все LLM-провайдеры недоступны), но дальше они превращались в строку в журналах контейнера. Никого не будили, на них нельзя было подписаться, повторные вхождения не схлопывались: outage провайдера выглядел как сотня разрозненных строк по числу PR.

## Причина

Не было внешнего сборщика ошибок. Все «пойманные» исключения глотались внутри процессов ingress/worker/sweeper и оседали в stdout контейнеров — это удобно для отладки на машине, но не канал алертинга: без тегов, без группировки, без ретеншена.

## Решение

Интеграция Sentry через новый модуль `reliability/sentry_setup.py`:

- `configure(service)` идемпотентна и необязательна: без `SENTRY_DSN` — no-op, локальный запуск/тесты/откат работают как раньше;
- инициализация в трёх точках входа (ingress `app.py`, worker, sweeper) с тегом `service=ingress|worker|sweeper`;
- два явных capture там, где сбой реально глотается: dead-letter в `worker.py` и полная недоступность LLM-шлюза в `gateway.py`; `fingerprint` по классу сбоя — outage одного провайдера = одно issue, а не сотня;
- `LoggingIntegration`: `logger.info` → breadcrumb, `logger.error` → событие.

Безопасность: `before_send`-скраббер вырезает секреты (`token/key/secret/private/authorization/diff/patch`) из значений переменных кадров стека и заголовков до отправки; тело webhook'а выбрасывается целиком. Живой смоук в облако Sentry: 3 события приняты, секреты отфильтрованы, повторные сбои схлопнулись в одно issue.

## Как проверить

```
cd self-hosted && python3 -m unittest discover -s reliability/tests -t . -v
```

167 тестов зелёные, включая 8 новых на скраббер и необязательность DSN. Вживую: задать `SENTRY_DSN` + `docker compose up -d --build` (SDK ставится слоем образа, нужен именно `--build`, не рестарт), затем в логах ingress — строка `sentry enabled: service=ingress`.

## Уроки

- «Пойманный» сбой без внешнего сборщика — всё ещё тихий: строка в журнале контейнера никого не будит, адресуемое событие с fingerprint — будит.
- sentry-sdk прикладывает к кадру стека строки исходника (pre_context): скраббер чистит значения переменных, но секрет-литерал в коде уедет в Sentry даже при живом скраббере — в проде секреты только из env, никогда литералами.
- `fingerprint` по классу сбоя — дешёвый способ превратить шторм событий при outage провайдера в одно issue.
