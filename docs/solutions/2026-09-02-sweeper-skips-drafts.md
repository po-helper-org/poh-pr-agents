# Свипер ревьюил черновики — обходил фильтр вебхука и жёг бюджет LLM

## Ситуация

Путь вебхука черновики пропускает и ждёт снятия статуса — так описано в README. Но reconciliation-свипер, обходящий открытые PR по расписанию, брал все открытые PR без фильтра: любой черновик в любом репозитории контура получал ревью зря.

## Причина

`parse_open_prs` в `self-hosted/reliability/sweeper_adapter.py` не имел ни фильтра черновиков, ни проверки стоп-меток: reconciliation-путь и webhook-путь расходились в правилах приёма. Появление черновиков стало массовым, когда соседний контур стал выкладывать работу сорвавшегося прогона черновым PR (заведомо негодная работа — ревью на неё тратиться не должно).

## Решение

Одна строка в `parse_open_prs` + тест: черновики отфильтрованы. Отсутствие поля `draft` считается обычным PR — так отвечают старые записи и часть API.

## Как проверить

```
python -m unittest discover -s reliability/tests -t .
```

276 тестов, зелено. Вживую: открыть черновик — свипер его не ревьюит; снять draft — попадает в оборот.

## Уроки

- У каждого периодического обхода («свипера») те же фильтры приёма, что и у событийного пути: расхождение правил = тихий обход всех защит.
- Небольшой фильтр, добавленный в обходной путь вовремя, экономит бюджет LLM на каждом черновике каждого репозитория контура.
